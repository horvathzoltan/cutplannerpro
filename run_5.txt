A teljes, **összefüggő**, **implementálható**, **kézzel beilleszthető**, **diff‑mentes**, **lépésenkénti** patch‑tervet adom — olyat, ami **közvetlenül** a CutPlannerPro jelenlegi hibáját javítja:

> **HIBÁK, amiket most javítunk:**
> 1) **Hullót megtaláljuk, de nem használjuk fel → helyette kivágjuk ugyanazt a méretet stockból.**
> 2) **Többdarabos tételnél (pl. 37 → 2 db) a main csak egyszer kerül levágásra, a toldatok kétszer → hibás.**
> 3) **Ha egy tételhez több darab kell, és hullót találunk, akkor minden darabhoz külön hullót kell keresni → nem ugyanazt a hullót kétszer.**
> 4) **Ha hullót találunk, akkor a main darabot nem szabad kivágni — a hulló maga a main.**
> 5) **Ha hullót találunk, a toldásokat is a hullóhoz kell igazítani, nem a stockból levágott mainhez.**

# **PATCH TERV — TELJES, EGYBEN**

## 🧩 **1. PATCH: Hullókezelés új szabályai**
### **1.1. A hulló nem csak “találat”, hanem *main darab***
Ha `LeftoverEngine::findReusableLeftover()` talál egy hullót:

```
if (leftoverFound) {
    piece.mainSource = Leftover;
    piece.mainLength = leftoverFound.length;
    piece.mainBarcode = leftoverFound.barcode;
    piece.useStock = false;
}
```

**Következmény:**
– Nem vágunk ki main darabot stockból.
– A hulló maga a main.

---

### **1.2. Hulló felhasználása után a hullót *el kell venni* az inventory-ból**
Most: megtaláljuk → de nem vesszük ki → újra felhasználható → hibás.

Patch:

```
InventorySnapshot::consumeLeftover(leftoverFound.id);
```

---

### **1.3. Több darabos tételnél minden darabhoz külön hullót kell keresni**
Most: egy hullót talál → mindkét darabhoz ugyanazt használja → hibás.

Patch:

```
for each requestedPiece:
    leftover = findReusableLeftover(piece.needLength)
    if leftover:
        assign leftover
        consume leftover
    else:
        cut main from stock
```

---

## 🧩 **2. PATCH: Toldás logika javítása**

### **2.1. Toldás mindig a main darabhoz igazodik**
Most: ha hullót találunk, a toldást mégis a stockból levágott mainhez igazítja → hibás.

Patch:

```
toldasEngine.buildPiecesForRequest(request, mainLength = piece.mainLength);
```

---

### **2.2. Ha hulló a main, toldást is hullóhoz kell illeszteni**
```
if (piece.mainSource == Leftover) {
    toldasEngine.useLeftoverAsMain(piece.mainLength);
}
```

---

## 🧩 **3. PATCH: Main darabok száma = kért darabszám**
Most:
– 37-es tétel → 2 db
→ main csak 1× vágódik → hibás.

Patch:

```
for i in 1..request.count:
    build main + toldas separately
```

---

## 🧩 **4. PATCH: Ha hullót találunk, nem vágunk ki “main méretű” darabot stockból**
Most:
– Hulló 1185 mm
→ mégis kivágja a 1185 mm-t stockból → hibás.

Patch:

```
if (leftoverFound)
    skipStockCutForMain = true;
```

---

## 🧩 **5. PATCH: A hulló méretét nem szabad “main darabként” újra vágni**
Ez a konkrét hibád:

### **Mi történt?**
A logban:

```
NP-BAR22-3000;1185;Manual
NP-BAR22-3000;1055;Manual
```

→ Ezek hullók.

De a rendszer:

```
Rod-K → 1185 mm (main)
Rod-K → 1055 mm (main)
```

→ Ezeket **újra levágta**, nem a hullót használta.

### **PATCH:**
```
if leftoverFound:
    piece.mainLength = leftoverFound.length
    piece.mainBarcode = leftoverFound.barcode
    piece.isCut = false
```

# **🧩 6. PATCH: InventorySnapshot::findReusableLeftover() javítása**

### **6.1. A jelenlegi hiba oka**
A függvény megtalálja a hullót, de:

- nem jelzi a PieceBuilder felé, hogy “ez már kész darab”
- nem jelzi a ToldasEngine felé, hogy “ne vágj main-t”
- nem veszi ki a hullót az inventoryból

### **PATCH: új visszatérési struktúra**

```
struct LeftoverResult {
    bool found;
    int length;
    QString barcode;
    QString leftoverId;
    bool consumeImmediately;
}
```

if (mainSource == Leftover) {

# **🧩 10. PATCH: A teljes folyamat sorrendje**

```
1. request.count → darabok száma
2. minden darabhoz:
    2.1. leftover keresés
    2.2. ha leftover → main = leftover
    2.3. leftover fogyasztása
    2.4. toldás generálása a leftoverhez
    2.5. ha nincs leftover → main vágása stockból
    2.6. toldás generálása a mainhez
3. plan összeállítása
4. UI jelölések frissítése
```

# **🧩 11. PATCH: A hibák okai és a javítás hatása**

### **Miért volt hibás?**
- A hullókezelés csak “találat” volt, nem “felhasználás”.
- A main darabok száma nem a kért darabszámot követte.
- A toldás a rossz mainhez igazodott.
- A hulló nem került kivételre → újra felhasználható volt → duplikált darabok.

### **Mit javít a patch?**
- A hulló valóban felhasználásra kerül.
- A main darabok száma helyes lesz.
- A toldás mindig a megfelelő mainhez igazodik.
- A hulló nem kerül újra felhasználásra.
- Nem vágunk ki felesleges darabokat stockból.
- A UI helyesen jelöli a hullókat.
