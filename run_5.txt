1.  Fázis – Fogalmak tisztázása

A group summary-ból szerintem el kell tűnnie ennek:

expandedGreedyStrands totalGreedyStrands

vagy legalábbis információs célra maradhat, de ne ez legyen a döntés
alapja.

Az üzleti fogalmak:

requiredDemand

az eredeti igény.

originalAvailable

az eredeti anyag fedezete.

alternativeAvailable

az alternatívák fedezete.

groupAvailable

a kettő összege.

2.  Fázis – Mit jelent egy csoport?

Most:

BW12

NP-BAR12-4000 (origin) NP-BAR12-3000 (alternative)

Valójában ez egy “coverage pool”.

Vagyis:

Need = original material demand

és

Have = original material stock + alternative material stock

3.  Fázis – Az új summary modell

Én ezt vezetném be:

struct InventoryAuditGroupSummary { QString groupKey; QString groupName;

    int requiredDemand = 0;

    int originalAvailable = 0;

    int alternativeAvailable = 0;

    int totalAvailable = 0;

    GroupCoverage coverage;

};

4.  Fázis – A coverage szabályrendszer

Definiáljuk pontosan.

✅ ORIGINAL

Az eredeti anyag önmagában elegendő.

originalAvailable >= requiredDemand

🔄 PARTIAL

Az eredeti önmagában kevés.

De:

originalAvailable > 0

ÉS

originalAvailable + alternativeAvailable >= requiredDemand

🔁 SUBSTITUTE

Nincs eredeti fedezet.

originalAvailable == 0

viszont:

alternativeAvailable >= requiredDemand

❌ SHORTAGE

A teljes csoport sem elég.

originalAvailable + alternativeAvailable < requiredDemand

5.  Fázis – Meg kell találnunk a megfelelő adatforrást

Itt jön a kritikus kérdés.

Most a summary ezeket használja:

snapshotStrands stockStrands

De előbb el kell dönteni:

Mit akarunk vizsgálni?

Készletfedezet?

Akkor:

stockStrands

kell.

Optimizer snapshot fedezet?

Akkor:

snapshotStrands

kell.

Szerintem a coverage jelentése:

A gyártás legyártható-e?

ezért:

stockStrands

az érdekes.

Nem:

snapshotStrands
