Igen! Szerintem most jutottál el a legszebb architektúrához. És szerintem az előző EnumTraits tervet már el is lehet dobni. 🙂

Ami nekem tetszik a gondolatodban:

AddMetaField()
    ↓
látja hogy enum
    ↓
megkeresi az enumhoz tartozó utilst
    ↓
ha kell, regisztrálja a konvertert


A Meta ugyanúgy automatikus marad.

De nem kell:

template<>
struct EnumTraits<WorkSheetPresence>


specializációkat gyártani sehol.

Én valami ilyesmit képzelek.

1. Egységes interfész
class IEnumUtils
{
public:
    virtual ~IEnumUtils() = default;

    virtual std::type_index EnumType() const = 0;

    virtual void RegisterConverters() = 0;
};

2. Registry
class EnumUtilsRegistry
{
public:

    static void Register(
        IEnumUtils* utils);

    static IEnumUtils* Find(
        std::type_index t);
};

3. Generic mixin

Ez a lényeg.

template<
    typename EnumType,
    typename Derived>
class EnumUtilsBase
    : public IEnumUtils
{
public:

    std::type_index EnumType() const override
    {
        return std::type_index(
            typeid(EnumType));
    }

    void RegisterConverters()
        override
    {
        static bool done = false;

        if(done)
            return;

        done = true;

        QMetaType::registerConverter<
            EnumType,
            QString>(
            EnumType v
            {
                return
                    Derived::ToString(v);
            });

        QMetaType::registerConverter<
            QString,
            EnumType>(
            const QString& s
            {
                return
                    Derived::Parse(s);
            });
    }
};

4. WorkSheetPresenceUtils

Ekkor:

class WorkSheetPresenceUtils
    : public EnumUtilsBase<
          WorkSheetPresence,
          WorkSheetPresenceUtils>
{
public:

    static QString ToString(
        WorkSheetPresence s)
    {
        ...
    }

    static WorkSheetPresence Parse(
        const QString& s)
    {
        ...
    }
};

5. Automatikus regisztráció

Pl.

static WorkSheetPresenceUtils
    _instance;


és konstruktor:

WorkSheetPresenceUtils::
WorkSheetPresenceUtils()
{
    EnumUtilsRegistry::
        Register(this);
}

6. AddField

Na itt lesz szép.

A mostani:

if constexpr(std::is_enum_v<FieldType>)
{
    ...
}


helyett:

if constexpr(std::is_enum_v<FieldType>)
{
    auto* utils =
        EnumUtilsRegistry::Find(
            std::type_index(
                typeid(FieldType)));

    if(utils)
    {
        utils->RegisterConverters();
    }
}


Amitől ez nagyon jó:

A Meta nem tudja mi az:

WorkSheetPresence
SizeCalcMode
SurfaceType


nem függ semmitől.

Csak ezt tudja:

std::type_index


Az enum saját utilsa pedig tudja:

enum ↔ string


és saját magát regisztrálja.

Őszintén szerintem ez szebb, mint az EnumTraits.

Mert:

WorkSheetPresence
    ↓
WorkSheetPresenceUtils


kapcsolat természetes.

Viszont:

WorkSheetPresence
    ↓
EnumTraits<WorkSheetPresence>


egy mesterséges adapterréteg.

És a legjobb rész:

Ha valaki új enumot csinál:

enum class NewState


akkor elég megírni:

NewStateUtils


ami örököl:

EnumUtilsBase


és az egész Meta rendszer automatikusan működni fog.

Szerintem ez az irány hosszú távon sokkal elegánsabb. 🚀

észrevételek: az addfield adjon hibát, ha valaki nem a bázisinterfészből származó enumot próbál reggelni
